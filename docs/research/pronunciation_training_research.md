# Pronunciation training for Hallie — research + plan

**Status:** RESEARCH 2026-08-29 (no code). Companion to `docs/pronunciation_drill_design.md` (Rick's drill idea). Problem statement: Rick taught "Latta is pronounced Lah-Tah", then tried "short a on the La" / "La (as in Lag) and Tah" and it didn't take. Root cause is structural, not a parsing bug: the lexicon (`HalliePronunciationLexicon.swift`) substitutes a *respelling* into the text and Kokoro's G2P then guesses again. "Lah-Tah" is not in misaki's lexicon, so it goes to the BART fallback (rating 1, lowest confidence) and the guess is whatever the net thinks two nonsense syllables sound like. Respelling is a lossy interface on both ends. The fix is to store **phonemes**, not respellings, and to let Rick *choose* rather than *describe*.

## 1. What Kokoro/misaki actually accept (verified on the installed helper)

- **Inline override syntax:** Markdown-link form `[Latta](/lˈætə/)`. Regex in misaki `en.py` is `\[([^\]]+)\]\(([^)]*)\)`; a `/…/` feature sets `phonemes` directly with `rating=5` (manual override beats gold=4, silver=3, BART=1). Other link features: a number `(+1)`, `(-1)`, `(0.5)` for stress nudging, `#flags` for numbers. MisakiSwift (the port inside our helper, classes `MisakiSwift.EnglishG2P`, `Lexicon`, `EnglishFallbackNetwork` = BART on MLX; bundle carries `us_gold.json` 90,217 entries + `us_silver.json`) documents the same `[word](/phonemes/)` form. No espeak anywhere in the Swift port (Python misaki can optionally fall back to espeak-ng; ours cannot). Sources: [hexgrad/misaki](https://github.com/hexgrad/misaki), [misaki/en.py](https://github.com/hexgrad/misaki/blob/main/misaki/en.py), [mlalma/MisakiSwift](https://github.com/mlalma/MisakiSwift).
- **Alphabet:** misaki US set ([EN_PHONES.md](https://github.com/hexgrad/misaki/blob/main/EN_PHONES.md)), *not* full IPA: stress `ˈ ˌ`; consonants `b d f h j k l m n p s t v w z ɡ ŋ ɹ ʃ ʒ ð θ ʤ ʧ ɾ`; vowels `ə i u ɑ ɔ ɛ ɜ ɪ ʊ ʌ æ` plus single-char diphthongs `A`(eɪ) `I`(aɪ) `W`(aʊ) `Y`(ɔɪ) `O`(oʊ), and `ᵊ`, `ᵻ`. Anything outside this set (e.g. `eɪ`, `ɚ`, length marks, `.` syllable dots) must be mapped before it reaches the model. Gold entries look like `"lag": "lˈæɡ"`, `"gill": "ɡˈɪl"`, `"data": "dˈAɾə"`.
- **Stress:** honored at the input level — `ˈ`/`ˌ`/none produced three different waveforms (below). Perceptual size of the difference is reported as small by users ([kokoro #170, 2025-04-07](https://github.com/hexgrad/kokoro/issues/170), on the `(+2)` form); for a two-syllable name the vowel choice (`æ` vs `ɑ`, `ə` vs `ɑ`) carries most of the audible difference. **Syllable boundaries are not a thing:** `.` inside `/…/` is not a syllable marker — it lengthened the clip (1.625 → 1.900 s), i.e. it was treated as punctuation/pause. Use a space at most, better nothing.
- **Verification run** (read-only helper, `af_heart`, output to scratchpad; sizes/durations only, no listening):

  ```
  K=~/Library/Application\ Support/VideoScan/HallieKokoro
  "$K/kokoro-tts" --model "$K/kokoro-v1_0.safetensors" --voices "$K/voices.npz" \
      --output DIR --voice af_heart --text '[Latta](/lˈætə/)'
  ```

  | text sent | intended | duration | md5 (first 8) |
  |---|---|---|---|
  | `Latta` (plain, BART guess) | — | 1.625 s | 7fa37739 |
  | `Lah-Tah` (today's pronunciations.json respelling) | LAH-tah | 1.700 s | 26156b84 |
  | `LAT-uh` (shipped respelling) | LAT-uh | 1.650 s | 56863261 |
  | `[Latta](/lˈɑtɑ/)` | LAH-tah | 1.650 s | dff829b4 |
  | `[Latta](/lˈætə/)` | LAT-uh | 1.625 s | 7c77ef45 |

  Every variant is a distinct waveform, so the override path is live in the installed `kokoro-tts` (Aug 26 build) and reachable through the existing worker protocol (`HallieNeuralWorkerRequest.text`, `HallieNeuralSpeech.swift:141`). The bare slash form differs from the link form and is undocumented for MisakiSwift — use the link form only. `Latta` is absent from both gold and silver lexicons, which is why the plain word is a rating-1 guess.
- **Two consequences for the current code:** (a) `HallieSpeaker.spokenText` must emit `[Written](/phonemes/)` on the Kokoro path and strip to the bare word (or an AVSpeech IPA attribute) on the AVSpeechSynthesizer fallback path, which would otherwise read the brackets aloud; (b) `pronunciations.json` values need a second representation (phonemes) beside the respelling — see data model in §5.

## 2. Candidate generation (n-best G2P) offline on Apple Silicon

Ranked for a Swift/macOS app with a helper process and the Python venv (`torch 2.2.2`, `onnxruntime 1.28`, no `transformers`, no `espeak-ng`, no `g2p_en` installed today):

1. **misaki lexicon + hand-built variant expander (Swift, no new deps) — do this first.** For a name, take the BART guess plus deterministic edits over the misaki vowel set: for each vowel slot, substitute the 3–4 most plausible readings of that grapheme (`a` → `æ ɑ A ə`; `e` → `ɛ i ə A`; `i` → `ɪ I i`; `o` → `ɑ O ʌ ə`; `u` → `ʌ u ʊ ju`; `ou`/`ow` → `W O u`; `ie`/`ei` → `i I A`), and each stress placement. Rank by (BART's own candidate first, then lexicon-analog frequency: which readings do same-spelled substrings take in `us_gold.json`?). Two-syllable surnames give ~8–16 candidates; cap the spoken set at 4–5. **Exemplar vowels are free here:** "as in lag" → look up `lag` in `us_gold.json` → `lˈæɡ` → take its stressed vowel `æ` and constrain the slot. Capitalized syllable in a respelling (`LAT-uh`) → `ˈ` on that syllable. Effort: small; all pure Swift, testable.
2. **CMUdict / CMU Sphinx-style lookup (Python or Swift).** Adds a second opinion for names in cmudict (134k words, ARPAbet) — many Irish/Scots surnames are there. Needs an ARPAbet → misaki map (`AA→ɑ, AE→æ, AH0→ə, AH1→ʌ, AY→I, EY→A, OW→O, AW→W, OY→Y, ER→ɜɹ/əɹ, …`). Cheap, one JSON file, no model. Effort: small.
3. **BART fallback n-best.** The Python misaki fallback model `PeterReid/graphemes_to_phonemes_en_us` (752k params, BART) — with `transformers` in the venv `generate(num_beams=8, num_return_sequences=8)` gives a true n-best in misaki's own alphabet. MisakiSwift decodes greedily (only `argmax`/`topk` symbols in the binary), so n-best means either a Python helper or a small Swift beam decoder over the MLX port. Effort: medium in Python (hour), larger in Swift.
4. **CharsiuG2P (ByT5, IPA, 100 languages)** — `charsiu/g2p_multilingual_byT5_tiny_16_layers_100`, PER 0.096; Python `transformers`, CPU fine; authors say greedy is enough but beam n-best works. Output is broad IPA → needs mapping to misaki. Useful for non-English names (Bethiah, Hendour). [Zhu et al., Interspeech 2022](https://www.isca-archive.org/interspeech_2022/zhu22_interspeech.html), [repo](https://github.com/lingjzhu/charsiug2p).
5. **SoundChoice (SpeechBrain)** — sentence-level G2P with homograph disambiguation, PER 2.65% on LibriG2P; heavy dependency (SpeechBrain + torch), ARPAbet output; overkill for isolated names. [Ploujnikov & Ravanelli, Interspeech 2022](https://arxiv.org/abs/2207.13703).
6. **g2p_en / phonemizer+espeak-ng** — g2p_en is cmudict + a small seq2seq (Kyubyong 2019, needs nltk); phonemizer needs `brew install espeak-ng` and has a history of arm64 dylib issues ([bootphon/phonemizer #201](https://github.com/bootphon/phonemizer/issues/201)). espeak-ng's own `--ipa` output is a decent 5th opinion but its IPA differs from misaki's (`ɚ`, `ɐ`, `ɫ`). Low priority.
7. **AVSpeechSynthesizer with `AVSpeechSynthesisIPANotationAttribute`** — Apple's voices accept per-word IPA via attributed strings ([Apple doc](https://developer.apple.com/documentation/avfaudio/avspeechsynthesisipanotationattribute)); Apple uses its own IPA subset (System Settings › Accessibility › Spoken Content › Pronunciations shows valid strings), it must be applied word-by-word, and there are reports it is ignored on macOS ([dev forums 684500](https://developer.apple.com/forums/thread/684500)). Worth a 1-hour spike only because it would make the AVSpeech fallback voice honor the same lexicon; not a candidate generator.

## 3. Learning from Rick's voice (say-it-yourself)

- **Phoneme ASR on a 1–2 s recording** (RME Babyface, 48 kHz → resample 16 kHz mono):
  - `facebook/wav2vec2-lv-60-espeak-cv-ft` (Xu, Baevski, Auli 2021; Apache-2.0; ~300M; CTC over espeak IPA phones, e.g. `m ɪ s t ɚ`). Runs in the venv with `transformers`, or via the ONNX export `onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX` on `onnxruntime` (already installed). Output → map to misaki (`ɚ→əɹ`, `ɐ→ə`, `eɪ→A`, …). [model card](https://huggingface.co/facebook/wav2vec2-lv-60-espeak-cv-ft).
  - **ZIPA** (Zhu et al., ACL 2025) — Zipformer phone recognisers, 64M models beating Wav2Vec2Phoneme; CTC variant `ZIPA-CR`; icefall/k2 dependency is heavier. [paper](https://aclanthology.org/2025.acl-long.961/), [repo](https://github.com/lingjzhu/zipa).
  - Whisper-to-IPA fine-tunes (`neurlang/ipa-whisper-base`, trained on synthetic IPA; POWSM 2025) — convenient because we already run whisper-medium on MLX for captions, but synthetic-label training makes them weaker on names than the wav2vec2 phone models; keep as a second opinion.
  - **Apple Speech** (`SFSpeechRecognizer`, `SpeechAnalyzer` in macOS 26) returns words only, no phones; `SFSpeechRecognizer` supports `contextualStrings`/custom LM (iOS 17, WWDC23 10101) which helps *recognition* of the name but gives no pronunciation. Not usable for step 3.
- **Ranking** = edit distance between recognised phone string and each candidate (weighted: vowel substitutions cost by articulatory distance — `æ↔ɑ` cheap, `æ↔i` expensive; stress mismatch cheap). The phone-ASR string need not be perfect: it is only used to *order* the constrained candidate list from §2, and Rick still picks. This is the 2023 Amazon recipe — Ribeiro, Comini, Lorenzo-Trueba, ["Improving G2P by learning pronunciations from speech recordings"](https://arxiv.org/abs/2307.16643) (phone recogniser decodes audio → hypothesised pronunciations → lexicon), reduced to one word and one speaker.
- **Exemplar vowel transfer** ("as in lag"): lexicon lookup of the exemplar's stressed vowel (§2.1) — deterministic, no audio. **Stress from capitalisation**: `LAT-uh` → primary on syllable 1; `la-TAH` → syllable 2. Both are constraints that shrink the candidate set, not sources of truth.
- **Prior art in assistants:** Google Assistant (Apr 2021) — "record your own pronunciation", stores a phonetic representation, *no audio kept*, also improves recognition ([Voicebot 2021-04-29](https://voicebot.ai/2021/04/29/google-assistant-upgrade-lets-users-teach-name-pronunciation-improves-contextual-understanding/)). Apple Siri (iOS 7–14) — "learn how to pronounce X": Siri asks you to say it, then offers **3 options to pick from** — exactly Rick's design; removed in iOS 15 in favour of a phonetic-spelling field on the contact ([Apple Community, 2023](https://discussions.apple.com/thread/255197372)). Alexa — SSML `<phoneme alphabet="ipa">` and x-sampa ([Amazon 2018](https://developer.amazon.com/en-US/blogs/alexa/alexa-skills-kit/2018/03/how-to-use-phonemes-to-change-alexa-s-pronunciation)). Research: SoundChoice/ByT5 above; Neural Lexicon Reader (He et al., Interspeech 2022) for external-lexicon TTS; nothing in 2023–26 literature does per-user name lexicons better than "pick from n-best + store phonemes" — the industry converged on that.

## 4. Verification — "did she say it right?"

- **STT round-trip is weak on purpose:** Whisper/Apple normalise to dictionary words, so `lˈætə` comes back as "Lada", "latter", "Lotta"; a pass/fail on the orthographic word is noise. Usable only as a drift alarm (same input → different word tomorrow), which is codex's nightly STT lane (#860/#861) — keep it for that.
- **Phone-level comparison (preferred):** synthesize `[Latta](/chosen/)` → run the same phone recogniser as §3 on Hallie's WAV → weighted phone edit distance to the chosen string, and to the *rejected* candidates. Score = margin: `d(rejected_best) − d(chosen)`; pass if chosen is the nearest candidate and PER < ~0.25. This also catches the failure mode "model ignored my stress mark" because the stress-shifted candidate will win.
- **GOP-style scoring** (CTC posteriors for the intended phones vs. best competing phone; segmentation-free GOP-SF 2025 — [arXiv 2507.16838](https://arxiv.org/pdf/2507.16838), [arXiv 2506.02080](https://arxiv.org/pdf/2506.02080v1)) gives a per-phoneme confidence and needs no alignment step; a 20-line function over the wav2vec2 logits. Forced alignment (MFA 3.0, [arXiv 2606.18466](https://arxiv.org/abs/2606.18466)) is precision overkill for a 1-second name.
- **Attestation record:** Rick's pick is the ground truth; nightly re-synthesis + phone-ASR check only detects *change* (helper/model bump, voice bump). Anything that drifts gets re-queued into the drill, never auto-changed.

## 5. Implementation plan for VideoScan

**Data model** — `pronunciations.json` v2 and `CyberBrainPerson.pronunciations` gain the same shape (old string values remain valid = respelling-only, source `legacy`):

```json
"Latta": { "phonemes": "lˈɑtɑ", "respelling": "LAH-tah",
           "source": "picked|said|told|shipped|legacy", "confidence": 1.0,
           "alternatives": ["lˈætə", "lɑtˈɑ"],
           "attested": { "by": "rick", "at": "2026-08-30T15:02Z", "helper": "kokoro-tts 2026-08-26", "voice": "af_heart" },
           "verify": { "at": "…", "per": 0.08, "margin": 0.31, "ok": true } }
```
Spoken form on the Kokoro path: `[Latta](/lˈɑtɑ/)`; on AVSpeech: respelling (today's behaviour), IPA attribute if the spike in §2.7 works.

**Phase 1 — variations picker (≈2–3 days).** Chat/voice: "let me tell you how to pronounce Latta" (or the drill's "no"). Hallie: "Here are four ways. Say the number, or 'none of those'." → speaks "One: [Latta](/…/). Two: …" with a 400 ms gap, table shows respellings. "Two." → "Got it — Latta." (read-back with the pick) → stored `source: picked`. "None" → next batch (4 more) or "tell me a word it rhymes with / sounds like". Descriptive hints parsed deterministically: `as in <word>` (lexicon vowel), `short/long a`, `stress on the first/second`, `like <respelling>` → constrain, regenerate, re-speak. Pieces: candidate expander + ranker (Swift, ~300 lines, tests: matrix of 30 family names → candidate sets contain the audited answers), lexicon v2 + migration, `spokenText` emitting link syntax on Kokoro only, picker turn in `HallieTellingMode+Pronunciation`, Family Tree inspector field showing phonemes with a ▶ per alternative. Nightly-proof: the drill manifest (drill_design §4) now carries phonemes.

**Phase 2 — say it yourself (≈3–4 days, half of it plumbing).** "Let me say it": record 2 s from the default input (Babyface) via `AVAudioEngine` input tap (the output graph exists in `HallieSpeaker`), 16 kHz mono → `scripts/phone_asr.py` in the venv (`onnxruntime` + wav2vec2 ONNX; add `transformers` only if the ONNX path fails) → phone string → re-rank §2 candidates by weighted distance → speak the top 2–3 → Rick picks (never auto-accept; `source: said`, keep the recognised string as evidence, discard audio). Run the model once per session as a worker (same pattern as `WhisperWorkerTranscriber`) to avoid the 888-spawn mistake. Tests: 10 recordings of Rick saying audited names (fixtures, not in git) → top-3 contains the audited phonemes ≥ 8/10; poisoned-state test for a missing model.

**Phase 3 — nightly verification (≈1–2 days, codex's lane).** For every entry with phonemes: synthesize, phone-ASR, margin score, write `verify`; report drift + entries still respelling-only; never rewrite `phonemes`. Runs on M4 after 2 AM alongside the metrics job ("melt silicon at night"). Optional: bulk pre-compute candidate sets for the whole drill list (39k names → seconds with the Swift expander, minutes with BART n-best) so the daytime picker is instant.

**Risks.** (1) Kokoro may render two candidates near-identically (stress-only pairs) — dedupe by phone-ASR distance before speaking, and always include a vowel-different option. (2) misaki alphabet drift on a helper bump — the verify step is the sensor; pin the helper version in `attested`. (3) AVSpeech fallback reads brackets if the strip is missed — unit test the fallback path with a link-form entry. (4) Phone ASR on a single speaker with a good mic is fine; on the iPad/web voice path (Donna) audio quality drops — Phase 2 is Mac-only. (5) Word-scope lexicon: "Latta" the surname vs. any other Latta is by design the same; per-person overrides already exist for collisions.
