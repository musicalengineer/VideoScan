Data flow: Ingest → Manage → Archive, around one catalog

1 · INGEST

Scan every drive (resumable, checkpointed)

ffprobe: container, codec, size, rate, scan

Whole-file SHA-256: the identity, never the path

One commit; no gate, junk skipped; provenance drafted here, required at Promote

2 · MANAGE

Catalog: identify, date, repair, search, inspect

Triage lens: Events (group by occasion), Cleanup (copies proved byte-for-byte, Trash only)

People and Family Tree enrich: who, born when, how related

Machine observations arrive with evidence; Rick confirms; a rejected value is never re-proposed

3 · ARCHIVE

Promote: copy to the Master Archive, filed by decade

Hash before and after; 00_Index manifest under a lock; append-only ledger line

Fixity re-read on cadence (Verify Catalog tiers 0–6)

Archived means fixed: only Rick changes a name or date, through Update…

Every stage reads and writes one catalog.sqlite through one commit door. Hallie reads everything and changes nothing. Analysis and the service only read media; Promote copies, Repair writes a new file, Trash moves — never unlink.

Shape borrowed from PBCore (one carrier, many files, each with a role) and PREMIS (a dated event log of who did what), at family scale.

Each column is one stage of the spine read top to bottom. The dark bar is the catalog every stage goes through. ARCHITECTURE §2 has the same table in words.
