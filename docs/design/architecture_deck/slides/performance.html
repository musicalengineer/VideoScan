Performance: where the time goes, and what the silicon does

Ingest one file — disk-bound, so one reader per drive and streaming everywhere

Read bytes — SSD fast, SMB and old USB slow · the bottleneck

SHA-256 — CPU, keeps pace with one SSD per core

ffprobe — milliseconds; cached by path, size, mtime

Commit — ~0.1 s on the main actor, by design; batched

Analyze one clip — GPU-bound: frames ripped by ffmpeg, then the 8B on the GPU; measured 6–12 s per clip, 6.7 GB resident

Rip 8 frames per window — disk and CPU, to a temp dir

Model prefill and decode — GPU, unified memory · the bottleneck

Validate and journal — fail-closed schema; one write and fsync per file

Apply — 256 lines per commit, off the main actor until the write

Limits and mitigations

  • Hallie and the era job share one GPU: the service trickles while Rick works, runs full at night
  • A model is loaded once per job, in a child process the watchdog can kill
  • Child processes stream; nothing reads a whole file into memory
  • No O(records) work in a view; indexes and counts are built off the main actor and debounced
  • A 15 MB/s drive is the real limit on ingest; the catalog is never
