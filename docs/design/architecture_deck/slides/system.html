Architecture and system context: the layers

VideoScan.app — the UI/UX and the one catalog committer

Six tabs and the Ask Hallie Mae window · every long job is a Media File Operation with Pause/Stop and a log line · applies the helper’s journal through the commit door

VideoScan Background.app — launchd helper

Keeps analyzing after the app quits · XPC control · reads the catalog read-only · writes an observation journal, never the catalog

VideoScanCore — the pure Swift package both processes link

Catalog store and the commit door (GRDB) · identity by whole-file SHA-256 · engines: fingerprints, date triangulator, prune plans, family graph · background jobs and the journal · the model lab types

Apple frameworks

SwiftUI · AVFoundation · Vision · Core ML · ServiceManagement (login item) · XPC

Swift packages

GRDB (SQLite) · MLX-Swift and mlx-swift-examples (on-device models) · swift-algorithms

Child processes

ffmpeg and ffprobe (all media I/O) · MediaInfo, dvrescue, ExifTool · Python workers: mlx-vlm (8B), mlx-whisper · Ollama (Hallie)

macOS 15+ on Apple silicon — unified memory, launchd, SQLite, Finder Trash, the file system, GPU and Neural Engine

Rule: analysis and the service only read media; Promote copies, Repair writes a new file, Trash moves (never unlink); every file operation runs ffmpeg through one streaming runner, never a bare Process. The helper never links the committer (a sensor proves it).

Top to bottom is dependency order. The two apps share Core; nothing in Core imports SwiftUI. Models never live in the app bundle: they sit in ~/.cache/huggingface and ~/.ollama.
