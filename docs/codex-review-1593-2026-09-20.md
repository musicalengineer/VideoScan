## Blocking deletion findings

1. **Newly unique target bytes can be deleted after quarantine.**
   `SignatureVerification.swift:337–338,364` deliberately ignores target ctime
   after rename (`ContentFixity.swift:87–88`). An existing open descriptor can
   rewrite the quarantined inode, preserving size and restoring mtime. Its
   inode/device/size/mtime still match, and the code deletes it even though the
   keeper now contains different bytes. Owner-only quarantine permissions do
   not revoke pre-existing descriptors.

   Exact-source repro: original keeper and target each contain 8 KiB of A;
   obtain a stored-keeper proof; use `didQuarantine` to write B through an already
   open target descriptor and restore mtime. Observed:

   ```text
   keeperReadInFull=false labels=["duplicate"]
   rewrittenAfterQuarantine=true fourFieldsMatch=true ctimeChanged=true
   result=deleted(bytes: 8192) targetExists=false keeperStillOriginal=true
   ```

   Harness: `/var/folders/d8/4gw97srj1gq4bwk2cnlklzwh0000gn/T/videoscan-fixity-review-0hk6lu7m/repro.swift`.
   Both reviewed source files were used with only module import removal and a
   `FileHasher.segmentSize` stub. Add this regression and bind final deletion
   authorization to the target contents across quarantine.

2. **Orphan recovery recursively deletes unrelated retained contents.**
   `DeleteDuplicatesJob.swift:568–571` chooses the first sibling quarantine
   containing the target basename, without saved transaction/file identity.
   `restoreQuarantined` line 588 recursively removes that directory after moving
   one file out, although its comment assumes the directory is empty.

   Exact-method repro: create `duplicate.bin` and an unrelated unique sentinel
   in one quarantine, then restore the duplicate. Observed:

   ```text
   result=success()
   restored_exists=true
   unrelated_unique_exists=false
   ```

   Harness: `/tmp/videoscan-review-1593-restore.swift`. Restore only an
   authenticated, unambiguous transaction and remove only an empty directory.
   Test unrelated contents, multiple same-name quarantines, wrong-content
   candidates, occupied original path, and restoration failure.

## Other changes required

3. **Authorization becomes stale after resume preflight.**
   `DeleteDuplicatesJob.swift:433–505` checks the batch at startup; dispatch at
   285–307 only requires keeper existence and target ID/path. Pause after the
   first pair, change the next target to keeper or archive-protected, change its
   group, or change the keeper's eligibility: dispatch still proceeds. Current
   cross-volume eligibility also is not fully re-established. Test a gated
   two-pair run; revalidate live authorization immediately before each dispatch.

4. **A live retained record can be falsely tombstoned.**
   `VideoScanModel+Duplicates.swift:456–459` falls back to a captured mutable
   `VideoRecord` class reference after the ID/path removal correctly refuses a
   changed row. Change that same instance's path during the disk await: fallback
   marks the retained row permanently deleted and logs its new path. Existing
   tests replace the instance, missing this aliasing case. Use immutable
   pre-operation facts for the removed-file event; do not mutate the retained row.

5. **Normal Quit can abandon rather than preserve the remaining plan.**
   `VideoScanApp.swift:204` calls `cancelAll`; job lines 374–411 skip all remaining
   entries and archive the finished plan. With async VLM shutdown drain
   (`VideoScanApp.swift:227–238`), cancellation can finish before exit, leaving no
   resume offer. Distinguish quit suspension from explicit Stop/abandon and test
   both immediate and delayed app-termination coordination.

6. **Final-save failure can hide the last good recovery plan.**
   `DeleteDuplicatesJob.swift:640` does not mark final-save failure; lines
   410–411 unconditionally move the plan to `done/`. If writes fail while renames
   remain possible, the old pending plan disappears from resume discovery.
   Gate archival on durable terminal persistence. Add initial, intermediate and
   final save-failure regressions, including recovery after failure.

7. **Known archive corruption leaves cached deletion authority intact.**
   `VerifyArchiveCopiesJob.swift:987–997` clears `archiveFixity` but not
   `contentFixity`. A verified corruption without stat changes leaves the cached
   old digest usable for deleting the intact counterpart. Revoke cached content
   fixity when an authoritative audit invalidates that file's fixity. Static
   finding; no silent-corruption injection was run.

8. **Remaining recovery offers require another launch.**
   `VideoScanModel+Duplicates.swift:524–538` clears/discards one offer without
   discovering the next. Completion likewise does not recheck; the production
   check is launch-only. The oldest-plan test calls it manually a second time.
   Add an actual discard/complete-to-next-offer transition test.

## Person documents

9. **Previous person's documents remain actionable under the next person.**
   `FamilyTreeLiveModel.swift:1933–1955` retains A's `selectedDocuments` while
   uncached B loads. `FamilyTreeView.swift:1877–1891` attributes Remove to current
   B, but the store derives the affected folder from A's document URL
   (`FamilyAssetStore+Documents.swift:405–410`). This permits removing A's
   certificate from B's inspector and misattributes the audit/cache update.
   Clear old rows on selection change, bind actions to ownership/revision, and
   revalidate confirmation. Test with B's read deliberately suspended.

10. **An older read can overwrite document invalidation.**
    `FamilyTreeLiveModel.swift:1913–1921` invalidates caches without changing
    `documentsGeneration`. An old async read may therefore finish after the
    refresh caused by import/removal and republish outdated entries/counts.
    Use per-person revision validation and test reversed completion order.
