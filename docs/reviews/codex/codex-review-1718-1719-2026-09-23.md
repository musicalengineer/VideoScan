### P2: blocking open prevents Stop and Pause

`FixityRebind.swift:80` opens with `O_RDONLY | O_CLOEXEC` before checking interruption or validating a regular file. If a previously catalogued path is replaced by a FIFO or points through a symlink to one, opening without a writer blocks indefinitely. The cancellation callback at line 93 is never reached. The manual job waits on this operation while holding its volume permit.

A bounded synthetic probe called the production rehash method with an already-stopped control and a FIFO. It still blocked beyond three seconds; the subprocess was killed and reaped. This is a demonstrated cancellation/liveness failure, not media loss or a UUID-trust bypass.

Check interruption before I/O, open without blocking on a FIFO, and use `fstat` to reject nonregular descriptors before hashing. A pathname check before `open` alone leaves a replacement race. Preserve the descriptor-bound before/after checks.

### P2: job reports saved progress without observing persistence

`BindFixityToVolumeJob.swift:215,219,226` calls only `saveCatalogDebounced()`, then reports completion or stopped-with-bindings-kept at lines 233/326. `CatalogStore.swift:888–903` delays writes for two seconds and resets the delay on each request. Repeated batches can defer checkpoints, and the job never observes a refused or failed save. Completion can therefore describe progress held only in memory.

Use the existing asynchronous acknowledged save for final/Stop persistence and meaningful checkpoints; handle failure before claiming durable progress. Ordinary app termination has a separate save path, so this is not a claim that every normal quit loses bindings. This finding is source-confirmed; no runtime persistence-failure test was executed.
